# Audience boundaries and private coaching memory

## Classify at intake
The agent owns classification; users need not label each sentence.
- `work-fact`: supported operational activity, outcome, decision, blocker or next step; potentially eligible only for an appropriate audience.
- `personal-assessment`: attributed impressions, opinions about people, relationship dynamics or inferred motives; internal only.
- `coaching-strategy`: private influence, facilitation or relationship approach; internal only.
- `unclassified`: requires assessment before reporting; never implicitly shareable.
Split mixed inputs into separate claims. Keep original mixed sources internal. Store subjective assessments as the speaker's dated view, not facts about a person. Preserve later changes of view and their dates. Do not infer traits or motives from operational observations.

## Select before drafting
Default ordinary reports, WhatsApp statuses, dashboards and demonstrations to `audience-report`. Use an established audience profile; if audience ambiguity changes permissible content, ask one targeted question or produce a conservative operational draft with the audience assumption stated outside it.
Select only supported work facts appropriate to that audience before drafting. Exclude assessments and strategies, including indirect revealing paraphrases. Never turn a private hypothesis into an apparent operational fact. Do not include a sensitive opinion merely because the name was removed.
Request `internal-reflection` explicitly before producing personal coaching notes. Label that output internal and keep it separate from outward reports; “internal status for colleagues” is not a request for personal reflection.
Work-fact classification is not permission for public release. Recipient scope, confidentiality and other-client boundaries still apply. A format choice or approval of report wording is not permission to send it.

## Review the entire deliverable
Check names in context, personal judgments, inferred motives, private tactics, indirect disclosure and cross-client information before handoff. Operational names/roles may remain when appropriate; do not prohibit all references to people.
For dashboards and exports apply selection to the actual payload: HTML, JavaScript, embedded JSON, comments, tooltips, modals, metadata, source excerpts and downloads. Do not embed internal notes and hide them with CSS or an internal-view toggle. If needed, create a separate explicitly requested internal artifact.
Keep private provenance in the private workspace. Audience artifacts must not link to mixed private journals or expose sensitive source text. Display only approved-for-audience source descriptions.
When uncertain omit the sensitive detail; clarify only when needed. Do not promise perfect confidentiality or present user review as the only safeguard.
Learn reusable preferences from corrections with provenance and scope; do not silently generalize a one-off disclosure exception.

## Public/private separation
Shared skills contain generic rules and synthetic examples only. Personal audience choices, actual assessments, client names, source excerpts and coaching strategies belong solely in the verified private workspace. Never copy a real person's example into public tests.
